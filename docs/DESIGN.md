# 设计说明

这份文档写给想改它或评估它的人。使用说明见根目录 `README.md`。

---

## 一、它解决什么问题

**1. 会话没有记忆。**
关掉窗口，模型就忘了你上周卡在哪。把状态写进文件、每轮再注入回来，记忆就变成可检查、可备份、可跨会话的实体。

**2. 多科会互相覆盖。**
计划会话想改档案，学科会话也想改档案。系统给每个文件规定唯一写者，越界写入在宿主层被拒绝。

**3. 学习状态不可审计。**
「这周做了什么」如果只存在于对话里，就无法核对。所有进度都落成带日期的行，任何时候都能打开文件对账。

## 二、三类会话 + 一组文件

```
                 运维（创造模式会话，人或模型）
                     │ 改 persona / 插件 / 规范
                     ▼
              ┌──── 重启或新会话才生效 ────┐
              ▼                            ▼
   学科会话                          总规划会话
   每轮自动注入：                     每轮自动注入：
   学习档案 / 本周任务 /              总规划看板 / 各科学习档案 /
   变更记录 / 课程路线摘要            变更记录
   └── 写：学习档案（上行） ──────────▶ 读
   ◀── 读：本周任务（下行，只读可勾选）── 写
       变更记录（广播，只有总规划能写）
```

三条通道各管一件事：

| 方向 | 文件 | 谁写 | 谁读 | 语义 |
|---|---|---|---|---|
| 下行 | 各科 `本周任务.md` | 总规划 | 该科会话 | 本周最小必做（每科 ≤3 条、≤2 KB，只能勾选） |
| 上行 | 各科 `学习档案.md` | 该科自己 | 总规划 | 进度、卡点、状态（≤6144 B / 60 行） |
| 广播 | `变更记录.md` | 总规划 | 全部会话 | 计划或基准改了什么（≤1 KB，不是任务单） |

**没有「沟通文件」这种中心枢纽。** 把任务、上报、广播拆成三份不同文件，是为了让每份都有明确的写者和上限。

## 三、四个关键机制

**1. 每轮自动注入（不是改系统提示词）**

学科会话启动时，`companion-core` 在 `agent/pre-step` 阶段把该科学习档案、本周任务、变更记录、课程路线摘要合成**一条快照消息**插进本轮上下文。

- 改文件 → 下一轮生效，不用重启
- 改 persona → 需要重启或开新会话

有去重缓存：内容没变不重复注入（零成本）；跨天强制重注入一次，保证「系统当前日期」基准是新的；上下文压缩后缓存作废。

**2. 一文件一写者**

`file-guard` 挂在**宿主平面**（不在预设里），所以标准预设、自定义预设都绕不过它。越权写入被拒绝并回执，而不是静默失败。`本周任务.md` 只允许把 `[ ]` 勾成 `[x]`，改任务文字会被拒。

**3. 判题、编译、靶场**

- `study-judge`：客观题判定
- `code-run`：真的把 C / Python 编译运行，把判定交给真实结果（不是让模型假装执行）
- `netsec-range`：本机最小靶场，用来练真实的越权、注入类题目

**4. 数据 → 单文件网页**

`tools/build-word-review.mjs` 把词表 JSON 构建成一个**没有任何外部请求**的单文件 HTML：翻卡、四档熟悉度、拼写本、遗忘阶梯（3/7/15/30/60 天）、随机抽卡。进度存在 localStorage。

## 四、目录结构

```
cordis.patch.yml      组合包补丁：宿主守护 + 「总规划」预设声明
study-suite.js        套件入口：按预设点名挂载 plan / companion / judge / code-run / netsec-range
companion-core.js     每轮注入快照 + 档案/任务的行数与字节上限
plan-core.js          看板生成、漂移检测、计划与任务结构守护
file-guard.js         一文件一写者（宿主平面）
study-judge.js        客观题判定
code-run.js           C / Python 真编译真运行
netsec-range.js       本机最小靶场
study-doctor.mjs      分层体检：坏在哪一层
run-all.mjs           回归入口（开发期）
new-subject.mjs       加一个科目（先校验、后落盘）
new-companion.mjs     建一个陪伴会话的骨架
tools/                构建器、预设读取、DSH 安装探测、会话日志解码
test/                 回归套件（开发期，见 test/README.md）
templates/            复习网页模板与应用主体
```

## 五、设计取舍

**文件是唯一记忆，不是向量库。**
检索系统适合「从海量资料里找相似片段」，而学习系统的状态是**少而结构化**的：这周的硬约束、每科卡在哪、哪些词到期该复习。用文件，人能直接打开核对、能 diff、能备份，也不需要为它跑一个服务。

**一个文件只有一个写者。**
宁可多一个文件，也不要一个文件两个作者——后者必然产生静默覆盖，而静默覆盖在学习系统里等于「进度丢了但没人知道」。

**校验在写入前，不在读出来时。**
`new-subject` 先生成、再用真正的校验器验一遍、验过才落盘。等到会话里被守护拒绝才发现，成本高得多。

**随包只带一个预设。**
装完就有的只有「总规划」；学科伴学由使用者按自己的科目、教材、考试自建。省下的不是代码，是「猜别人怎么学」的错误率。

**科目与预设的对应写在配置里，不写在代码里。**
学习根下的 `.科目预设.json`（`{ "科目目录名": "预设显示名" }`，可选）决定身份自检点名哪个预设；没有这个文件就只做通用提醒。产品里不固化任何一个人的科目清单。

## 六、边界

- **不含任何学习数据**：没有词表、档案、错题、计划。数据属于使用者，不进仓库。
- **不提供 DSH 本体与模型账号**：本套件跑在 DSH 里，这是前提。
- **`test/` 是开发期工具**：运行时不加载，只在改完插件后跑（见 `test/README.md`）。
