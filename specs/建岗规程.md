# 建岗规程：用「创造模式」建一个学科伴学预设

套件只随包交付「总规划」一条预设。学科岗位由学员用创造模式建——这样每一科的 persona 才是按他自己的需求长出来的。

## 步骤

1. **建目录**（在插件目录下，`--root` 指到你的学习根）：

   ```powershell
   node new-subject.mjs 数学 --outline --root "D:\学习"
   ```

   会建 `D:\学习\数学\学习档案.md`，先校验再落盘，写不进去会回滚。

2. **建岗位**：新建一个「创造模式」会话，把下面这段贴进去（改科目名与目录）：

   ```
   按 <插件目录>\specs\会话规范.md 与 specs\建岗规程.md，给我建一个「数学伴学」预设：
   - 显示名「数学伴学」，order 取一个没被占用的值；
   - 挂 study-suite 的 companion 与 judge 两个部件（要真跑代码再加 code-run，网安加 netsec-range）；
   - persona 按 specs\会话规范.md 的七段写，记忆判据引用 specs\记忆规范.md；
   - 会话工作目录是 D:\学习\数学；每轮读该目录的 学习档案.md 与 本周任务.md。
   ```

3. **重启 DSH**（完全退出再打开）→ 选择器里出现「数学伴学」。

4. **开课**：新建会话选「数学伴学」，工作目录必须指到**科目目录**（不是学习根）。第一句可以说「带我过一遍这门课的进度」，它会建 `课程路线.md`、`复习提纲.md`。

## 验收（5 条，缺一条就是没建好）

1. 选择器里有这个岗位，且只有一个同名；
2. 会话工作目录 = 科目目录；
3. 首轮注入里出现「学习档案.md」的字节数与「本周任务」；
4. 让学员说一句「记住：作业系统不限时」，回复里有回执，`学习档案.md` 或 `课程路线.md` 真的多了一行；
5. 换一个科目再建一个，两边档案互不覆盖（写守护会拒跨科写）。

## 常见错

- **岗位建在 web profile、桌面端看不到**：预设声明必须写进你正在用的那份 profile。
- **工作目录指到学习根**：注入找不到档案，等于没建。
- **一科多个同名预设**：选择器里会出现两个，写守护按目录判断归属，容易串。
- **persona 里写死绝对路径**：换机器就断，用工作目录相对路径。
